Calculation modes, maps and continuation

Manual home · Input reference · Output schemas

The executable reads one input file, builds species responses, and follows the calculation dictated by option. The same production dispersion evaluator and secant root method serve kinetic, cold and mixed systems. Note that the cold and kinetic geometry restrictions differ, so consult the capability matrix before requesting diagnostics. Create the input's data/<dataName> directory and use distinct output names.

Supplied guesses and direct evaluation

Provide guess_1 through guess_nroot_max with g_om=omega_r/Omega_R and g_gam=gamma/Omega_R. For root refinement, two nearby points are constructed from the guess and passed to the existing complex secant method. These are not guaranteed brackets. Several guesses can converge to the same branch or fail. A negative gamma is a damped mode under exp(-i omega t).

Existing single-wavevector examples:

mkdir -p data/example
./plume.e inputs/example/cold_proton_electron.in
./plume.e inputs/example/mixed_cold_protons_warm_electrons.in

For option=-1, test_disp evaluates only the first supplied frequency as-is and prints the determinant and default diagnostics.

The raw API determinant is . Direct stdout for a warm reference historically displays det(Lambda)*solver_vtp^6, while a cold reference displays the raw determinant. Numerical methods defines the matrices and scaling. Never compare these differently scaled numbers as if they were the same residual.

Frequency-map search

A map samples complex frequency grid points at fixed plasma and wavevector . Local minima of determinant magnitude serve as the seeds for secant refinement. Successful candidates are deduplicated using the historical absolute frequency gap 1e-5. The internal candidate storage is 500, not a user-selectable input. A minimum is not necessarily a physical zero, and a map cannot guarantee that all branches were found. Map resolution and bounds require carefuly user selection, some physics knowledge, and/or a convergence study.

The workflow distinguishes:

  1. Grid points: every sampled determinant, written to .map, including invalid points as NaN on guarded paths.
  2. Refined candidates: roots found and deduplicated before final selection, written to .roots. These are not grid frequencies.
  3. Selected roots: subsequent filters include and,
    when positive_roots=true, .
  4. Continued branch slots: scans follow nroot_max slots using the existing continuation. They do not continue every .roots row.

nroot_max is the supplied-guess/continuation count, not a cap on lines in .roots. The file is written before the later map filters. The optional internal sorting block is disabled by default, so do not assume branches are automatically ranked by least damping.
For incomplete searches, inspect candidates and initialize a bounded supplied-guess run deliberately.

The existing example_map_par.in is a secondary map lesson, not the introductory run:

./plume.e inputs/example/example_map_par.in

It writes data/example/dispersion_map_par.map and .roots (and any scans requested by the file). Use the matching input to interpret units. The audit found more .roots rows than nroot_max here; this is expected from writer order.

The origins are exponent-like, while increments use physical-bound ratios. Neither an exponent-bound convention nor a physical-endpoint convention explains both. Real logarithmic endpoints must be positive and imaginary magnitudes nonzero for these logarithms to exist; all imaginary input signs are discarded and the result is negative. Serial wavevector scans

Set option=1 and give nscan indexed scan_input_N groups. After initialization, they run serially, passing the last state into the next scan. These scans are not independent resets. Match the initial input wavevector and supplied root to the first scan point, particularly for the unchanged kinetic-only initialization.

For an ordinary scan, M=ns*nres continuation intervals are traversed. The code writes the endpoints and every nres-th point, normally ns+1 rows per branch. Hidden substeps help continuation but do not add rows. Positive logarithmic wavevector scans interpolate log10 of coordinates consistently.

Two-dimensional wavevector grids

Use option=2, nscan=2. Supported coordinate pairs are distinct Cartesian kperp/kpar axes, or ordered polar axes (scan_input_1 angle, scan_input_2 magnitude). The first scan is outer and the second is inner. Each coordinate uses its own ns/nres; output has blank separators between outer blocks. The existing large example_guess_double.in provides an example, see the examples index for more.

Eigenfunctions and heating in the grid use scan_input_2 switches. Tensor output requires tensor=.true. in both groups. The code preserves original species order and native coordinates.

Root failure and continuation

Successful points reuse the existing last-root continuation strategy. Guarded scan refinement checks finite roots/tensors, status and a determinant scaled by the maximum wave-matrix element. A failed written point has NaN root/diagnostic slots, with parameters retained; a failed hidden point warns without adding a row. The continuation seed remains the last valid one.

Near crossings, poles, strong damping or genuine branch termination, forward and reverse traversal can choose different branches. Check residuals, polarization and isolated single-wavevector refinements; reduce step size deliberately rather than assuming file continuity proves branch identity.

Repeated maps and historical parameter/radial workflows

Option=4 remaps at each scanned point rather than continuing a root. It accepts only one scan. Eigen/tensor flags and legacy heating are ignored with warnings; corrected map heating is rejected. Files remain determinant maps and candidate roots, without supplementary blocks. Use a separately initialized supported root/scan workflow for diagnostics. No heating is added to maps.

Collisionless, all-kinetic rho_ref runs support corrected heating in serial parameter scans and 2D grids. Global beta and vtp, and each population's tauS, muS, alphS, Qs, Ds and vvS, retain their existing input meanings. Scalar axes may appear in either order; both axes are validated, while scan_input_2 alone selects grid eigenfunctions and heating. The existing ordered theta/magnitude geometry convention is retained.

Each point is constructed from the segment or grid's initial native state, then the derived solver normalization is refreshed. Initial root selection uses the first scan point. Inner-axis parameters are reset before continuing the outer axis; later serial segments retain the preceding segment's final parameters. Frequency derivatives hold the current plasma and physical wavevector fixed, not a neighboring point along the parameter trajectory.

Parameter bounds must be finite, with positive beta, vtp, temperature ratios, mass ratios and anisotropies, nonnegative density ratios, and charge ratios that neither reach nor cross zero. Logarithmic coordinates require positive bounds; signed charge and drift scans can use linear spacing. Scan counts must be positive and their product must fit the integration index. Duplicate grid targets and overlapping wavevector axes are rejected. No wavevector floor is introduced.

Changing density, charge or drift does not automatically compensate another population or change reference frame. Charge/current imbalance and reference drift produce warnings, not enforced neutrality conditions. A zero-density population has unavailable relative density/bulk moments and kinetic heating; its parameters and availability statuses remain in the output. Field/growth applicability restrictions still apply independently of scan support.

Corrected parameter heating remains restricted to all-kinetic rho_ref runs; existing d_ref parameter scans retain their historical behavior. d_ref beta and reference tau scans synchronize each other; independent 2D variation is rejected. Temperature scans cannot reach or leave tauS=0. Normalization explains why a beta scan follows different physics in the two conventions.

Option=5 is experimental radial interpolation. It reads modelName0.rad for radius/beta/vtp and modelNameN.rad for each species' six parameters, and selects one of seven k_range layouts using k_scan=0..6. It is all-kinetic, with legacy radial heating only; corrected heating and cold species are not yet supported. Input fields and exact old record layouts are retained in Input and Output.
