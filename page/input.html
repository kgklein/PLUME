Input reference

Manual home · Normalization · Modes

This reference covers the 89 distinct case-insensitive input names used by PLUME. They are invoked across 14 namelist definitions, where seven alternative k_range layouts share names. The tables describe the parsers and checks. The source of truth is functions.f90 namelists andvars.f90 initialization.

Syntax and required values

An input file uses &params ... /, then indexed &species_1 through &species_nspec namelists, plus maps/guesses/scans/FPC/radial groups as selected. Put each indexed header alone on a lowercase line, without a trailing comment. The custom indexed extractor is case-sensitive even though scalar field names are not. Ordinary commas or newlines can separate scalar assignments. Quote character values and use .true./.false. for clarity. Supply all required species values, including a placeholder alphS for cold species. See the complete working annotated Quick Start.

In the below table, “No safe default” means there is no explicit initialization establishing a public value: supply it whenever the group/workflow uses it. A default removes the requirement to write that particular value.

Common public links: physical parameters, species classification, scan semantics, heating convention, numerical backends, FPC restrictions, output schemas.

nK and nk are the same case-insensitive parameter. Model tables contain radius in the first column, then beta/vtp in modelName0.rad or the six species parameters in modelNameN.rad. nRad sets rows, nRad_sub interpolation substeps. radial_eigen/radial_heating concern radial continuation; rad_eigen/rad_heat are stored on the auxiliary wavevector-range scan. This historical two-level interface has no primary curated example and should not be generalized without separate validation. The existing synthetic radial test is the developer reference.

Interactions and validation gaps

  • Cold-containing inputs require d_ref, collision_type=0, no FPC, and only supported wavevector scans. Cold references require betap=0; warm d_ref references require tauS_1=betap within the implemented relative comparison.
  • Warm-reference adaptation needs positive reference beta, vtp and physical anisotropy. Cold anisotropy is ignored.
  • Modern selectors and Bessel count/tolerance bounds are checked explicitly. Many old finite/count/storage/bound/Kn/FPC-grid checks remain incomplete.
  • Self mass/charge/density ratios are a user consistency responsibility; the old mass-ratio warning is nonterminal and not a comprehensive reference check. Charge neutrality, zero current and reference drift are warning-only, not imposed equilibrium constraints.
  • All-kinetic kperp=0 warns but remains unsupported. Every wavevector scan excludes kpar=0, including hidden points. Do not replace it with an arbitrary small floor. This will be updated in a future release
  • Map eigen/tensor and legacy heating requests warn and remain ignored; corrected map heating is rejected. See Modes rather than assuming that a flag implies a diagnostic file exists.

Python wrapper contract

linfpclib.linfpc.plume_input supports the scalar params/species/maps/scan/guess/ fpc groups above. It preserves low_n, both log flags, nr/ni, tensor and all Cartesian FPC bounds on read/write roundtrips. writeOut is independent of use_map, and positive_roots is independent of loggridw.

set_maps(loggridw, omi, omf, gami, gamf, positive_roots, loggridg=False, nr=128, ni=128) retains its historical first six arguments. make_scan(..., tensor=False) adds an optional tensor flag. Logical values in wrapper dictionaries use canonical Fortran strings. Quoted paths, comments, D exponents and scalar logical variants are supported.

load_from_file replaces prior indexed state, preserves an explicit dataName, and rejects unknown fields/unsupported groups or array/expression syntax instead of silently dropping controls. Assign obj.dataname after loading to redirect output. write_input still takes an explicit outputname. Radial/k_range groups are not supported by this wrapper. It is not a general Fortran namelist parser. Examples and executable reader code are on Output.
